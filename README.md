## 한눈에 보는 결과

심사 축 **RAG · 신뢰도 · 보안** 세 가지에 대응하는 숫자입니다. 전부 재현 명령이 있습니다.

| 축 | 무엇을 증명하나 | 수치 | 재현 |
|---|---|---|---|
| **보안** | 권한 없는 청크가 검색 후보에 오른 적이 있는가 | **895조합 전수 검사, 반례 0건** (표본 아님) | `python eval/permission_matrix.py bm25` |
| **신뢰도** | 근거가 없을 때 실제로 거절하는가 | **거부 37/37, 함정 12/12** (Upstage 전체 평가) | `$env:EMBED_BACKEND="upstage"; $env:GEN_BACKEND="upstage"; python eval/evaluate.py` |
| **RAG** | 자기 도메인 질문에 맞게 답하는가 | **100/107 (93%, 95% CI 87-97%)** Upstage 전체 파이프라인 | `$env:EMBED_BACKEND="upstage"; $env:GEN_BACKEND="upstage"; python eval/evaluate.py` |
| **RAG (온프렘)** | 외부 API 없이도 되는가 | **홀드아웃 49/53 (92%, CI 82-97%)** BGE 앙상블 | `$env:EMBED_BACKEND="bge"; python eval/evaluate.py --compare` |

측정 대상: 가상 기업 한성산업 사규 **26종 / 183청크**(live 179), 골든셋 **107문항**.

골든셋은 두 축으로 분류합니다. **두 축은 같은 107문항을 다르게 나눈 것이지 더하는 것이 아닙니다.**

| 축 | 분류 |
|---|---|
| 유형(`kind`) | 정상 54 / **부서한정 24** / 권한 14 / 함정 12 / 충돌 3 = 107 |
| 기대(`expect`) | 답변 70 / 거부 37 = 107 |

`evaluate.py`의 개발셋·홀드아웃 분리는 **유형 축으로 층화**합니다(`split()`).
한쪽에 함정이 몰리면 비교가 성립하지 않기 때문입니다.
임계값은 **개발셋 54문항으로 튜닝하고 홀드아웃 53문항으로 보고**합니다.

> **모든 비율에 표본 수와 95% 신뢰구간을 붙였습니다.** n이 작을 때 비율 하나는
> 측정이 아니라 일화이기 때문입니다. 겹치는 신뢰구간을 두고 우열을 단정하지 않습니다.

## 심사 축별 요약

### 1. RAG - 실제 업무 문제를 푸는가

신규 입사자가 사규를 물으면 **조항 단위로 인용된 답**을 받습니다.
청킹이 `## 제N조` 헤딩 단위라 답변의 출처가 "문서 이름"이 아니라 **"문서 / 제N조"**이고,
**시행일**이 함께 붙습니다. 사규는 개정되므로 낡은 조항을 최신으로 오인하는 것이 이 도메인의 실제 사고입니다.

폐지된 조항 4개는 `superseded`로 표시해 검색 후보에서 뺍니다 (183청크 중 live 179).

### 2. 신뢰도 - 모를 때 멈추는가

거부를 **3겹**으로 막고, 그 성능을 숫자로 냅니다.

| 겹 | 위치 | 비용 | 무엇을 잡나 |
|---|---|---|---|
| 1겹 | LLM 호출 **전**, 유사도 임계값 | **0** | 근거가 아예 약한 질문 |
| 2겹 | 생성 호출 안의 충분성 JSON (`ok`/`missing`/`use`) | 0 (같은 호출) | 문서 어휘를 쓰지만 답이 없는 고난도 함정 |
| 3겹 | 인용 대조 | 0 | 검색 결과에 없는 출처를 지어낸 경우 |

**측정 결과**: 거부해야 할 37문항 중 **37건 거부**, 함정 12문항 중 **12건 거부**(Upstage 전체).
오거부(답이 있는데 거부)는 홀드아웃 앙상블에서 **3/36**입니다.

**오거부율을 지표로 정의한 것이 핵심입니다.** 전부 거부하는 시스템도 거부율은 100%가 나옵니다.
정답률만 보면 과잉 거부를 못 잡습니다.

### 3. 보안 - 권한이 검색 단계에서 걸리는가

**등급 × 부서·직책의 2차원 ACL**입니다. 판정은 `config.visible()` 하나뿐입니다.

- 인사기획팀도 **재무 대외비는 못 봅니다** (등급이 아니라 부서가 막습니다)
- 부서 한정 `internal`은 대외비가 아닌데도 타 부서에서 막힙니다
- 권한 없는 청크는 **LLM 프롬프트에 오르지 않습니다.** 프롬프트에서 가리는 방식은
  인젝션 한 번에 원문이 새어나갑니다

**전수 검사**: live 179청크 × 페르소나 5 = **895조합, 반례 0건.**
표본이 아니라 전량이므로 신뢰구간이 없습니다. 반례가 있거나 없거나 둘 중 하나입니다.

## 데모 시나리오 (3분)

```bash

```

아래 5단계는 **골든셋에 들어 있는 문항이고, 각 수치는 실제로 돌려서 얻은 값입니다.**
괄호 안은 최고 유사도 / 임계값 / 권한으로 차단된 청크 수입니다.

**측정 조건: 온프렘 모드(BGE-M3) · `ensemble` · 임계값 0.63.**
임계값은 백엔드마다 다릅니다(`config.ABSTAIN_THRESHOLD`). Upstage로 돌리면 0.46이라
점수 눈금이 달라지므로 아래 숫자와 같지 않습니다. 거부/답변 판정 자체는 같습니다.

| # | 계정 | 질문 | 결과 |
|---|---|---|---|
| 1 | 개발본부 사원 | "연차는 사용 며칠 전까지 신청하나요?" | 답변. 출처 `[문서 / 제N조]` + **시행일** |
| 2 | 개발본부 사원 | "과장 직급의 연봉 밴드가 어떻게 되나요?" | **거부** (0.620 / 0.63, 차단 **54**) |
| 3 | **인사기획팀으로 전환** | 같은 질문 | **답변** (0.645, 차단 36). 1순위 `PAY-2026-402` |
| 4 | 인사기획팀 그대로 | "정기감사는 얼마나 자주 실시하나요?" | **거부** (0.532 / 0.63, 차단 36) |

**4번이 이 프로젝트의 핵심 장면입니다.** 인사기획팀은 등급상 `confidential`을 볼 수 있는데도

이 상황을 **표현조차 할 수 없습니다.**

2번과 3번은 같은 질문에 계정만 바꾼 것이고, 4번과 5번도 마찬가지입니다.
두 쌍 모두 골든셋의 `permission` 문항(P01/P02, P07/P08/P09)이라 **채점 대상**입니다.
시연에서 보이는 동작과 발표에 쓰는 숫자가 같은 문항에서 나옵니다.

근거가 아예 없는 질문(예: "회사 창립기념일은 며칠인가요?", 골든셋 `T01`)은 어느 계정으로도

## 이 프로토타입이 다른 점

일반적인 RAG 데모는 "검색 후 생성"까지만 합니다. 여기에 셋을 더했습니다.

1. **거부** - 근거가 없으면 지어내지 않고 답변을 거부합니다.
2. **권한** - 등급(public/internal/confidential)과 부서·직책이 **직교하는 2차원**입니다.
   인사팀도 재무 대외비는 못 보고, 부서 한정 internal은 대외비가 아닌데도 막힙니다.
   판정은 `config.visible()` 하나뿐입니다. 검색 후보 자체를 줄입니다.
3. **측정** - 골든셋 107문항으로 정답률·오거부율·함정 거부율을 **신뢰구간과 함께** 냅니다.

대형 RAG 프레임워크 4종(RAGFlow · Dify · LangChain · Langflow)의 소스를 대조한 결과,
거부를 *하는 것*은 저희만의 것이 아닙니다. RAGFlow 에이전틱 경로는 구조화 충분성 JSON
(`is_sufficient` / `missing_information` / `useful_chunk_ids`)과 질의 재작성 루프를 갖고 있습니다.
저희는 그 JSON 형식을 생성 호출 안에 흡수했고, 세 지점에서 다르게 닫습니다.

- **LLM 전에 거절한다.** 튜닝된 유사도 임계값(1겹)으로 호출 자체를 생략합니다. RAGFlow
  `similarity_threshold` 기본값 0.1은 튜닝된 값이 아닙니다.
- **불충분하면 거절한다.** RAGFlow는 재검색 루프가 끝나도 `partial_answer`로 잔여 근거를
  답으로 내보냅니다. 저희는 그 지점을 거절로 닫습니다.
- **재작성 루프는 넣지 않는다.** 검색 순위가 병목이 아니고 (BGE MRR 0.976, 정답 문서 70/70 후보 안),
  로컬 7B 한 호출이 35~86초라 루프는 시연을 죽입니다.

2번과 3번이 실제로 희소합니다. 근거는 [`CLAUDE.md`](CLAUDE.md) §1.1에 있습니다.

## 빠른 시작

```bash
git clone <this-repo>
cd FC_Hackathon
python -m venv .venv                  # 전용 가상환경 권장 (아래 주의 참조)
.venv\Scripts\activate               # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt

cp .env.local.example .env.local     # 가진 키만 채우세요. 전부 비워도 됩니다.

python src/ingest.py                 # 인덱스 생성 (커밋된 인덱스가 있으면 생략 가능)
streamlit run app.py
```

**Windows 주의**: 이 저장소는 `python3`가 아니라 `python`을 씁니다.
PowerShell에는 `export`와 `VAR=x cmd` 문법이 없습니다. `$env:NAME="..."`를 쓰세요.

**전용 venv를 권장하는 이유**: 이 프로젝트는 `fastapi`를 쓰지 않지만, 시스템 파이썬에
다른 도구가 깔아둔 오래된 `fastapi`가 있으면 그것이 `starlette` 버전을 묶어 `streamlit`이
기동하지 못합니다. 깨끗한 venv에는 `fastapi`가 설치되지 않으므로 이 문제가 아예 없습니다.

<details>
<summary><b>이 오류가 나면</b>: <code>ImportError: cannot import name 'DEFAULT_EXCLUDED_CONTENT_TYPES'</code></summary>

환경에 오래된 `fastapi`(`starlette<0.42`를 요구)가 있는데 `streamlit>=1.57`이 그보다 새로운
`starlette`를 필요로 해서 생기는 충돌입니다. **이 저장소의 의존성 문제가 아닙니다.**

해결은 둘 중 하나입니다.
- 깨끗한 venv를 만든다 (권장). `fastapi`가 안 깔리므로 충돌 조건이 사라집니다
- 기존 환경을 쓴다면 `pip install "streamlit<1.57"`. 1.57 미만은 tornado를 쓰므로
  `starlette`를 아예 임포트하지 않습니다. 이 앱은 1.57+ 기능을 쓰지 않습니다

`requirements.txt`에 상한을 걸지 않은 이유: 이 충돌은 **다른 도구가 오염시킨 환경에서만**
발생합니다. 그것 때문에 모든 사용자를 낡은 버전에 묶는 것은 맞지 않습니다.
</details>

### 키가 하나도 없어도 됩니다

`.env.local`을 비워도 **BM25 검색, 권한 필터 전수 검사, 검색 평가가 전부 그대로 돌아갑니다.**
이 프로젝트의 보안 축과 측정 축은 외부 서비스에 의존하지 않습니다.

| 가진 키 | 임베딩 | 가능한 검색 | 답변 생성 |
|---|---|---|---|
| **없음** | - | **BM25** | 안 함 (검색 결과만 표시) |
| `ANTHROPIC_API_KEY` | - | **BM25** | Claude |
| `UPSTAGE_API_KEY` | solar-embedding-1-large (4096차원) | dense / BM25 / 앙상블 | Solar |
| `OPENAI_API_KEY` | text-embedding-3-small (1536차원) | dense / BM25 / 앙상블 | GPT |

**Anthropic에는 임베딩 API가 없습니다.** 앤트로픽 키만 있으면 생성은 되지만 dense 검색은

### 검색 방식 3종 비교 (BGE, 홀드아웃)

```bash

```

개발셋 54문항으로 임계값을 튜닝하고 **홀드아웃 53문항으로 보고**합니다.
구 골든셋 40문항에서 온 ensemble 0.56은 폐기했습니다.

| 방식 | 임계값 | MRR | 정답률 | 함정 거부 | 오거부 |
|---|---|---|---|---|---|

### 앙상블 가중치는 어떻게 정했나

```bash
python eval/evaluate.py --alpha-scan      # 개발셋만 사용, 홀드아웃 미사용
```

아래 분리도는 **구 골든셋 40문항** 개발셋에서 측정했습니다. alpha 0.8은 그 이후 유지합니다.

MRR로 alpha를 고르려 했으나 그 데이터에서는 **모든 alpha에서 1.000이라 변별력이 없었습니다.**
대신 **분리도**(답변 가능 문항의 점수가 거부 문항의 점수보다 높은 쌍의 비율, 임계값과 무관)를 썼습니다.

| alpha | 0.0 | 0.3 | 0.5 | 0.7 | 0.8 | 0.9 | 1.0 |
|---|---|---|---|---|---|---|---|
| 분리도 | 0.727 | 0.755 | 0.800 | 0.827 | **0.836** | 0.836 | 0.836 |

0.8~1.0이 동점이라, 조항 번호·부서명 같은 정확한 어휘 일치를 위해 BM25 신호를 남기는
**낮은 쪽(0.8)**을 택했습니다.

**정직하게 밝힙니다**: 구 홀드아웃에서 alpha 0.5가 16/19로 1문항 더 높았습니다.
그러나 홀드아웃을 보고 alpha를 되고르면 그것은 더 이상 홀드아웃이 아닙니다.

## 설계상 바꾸면 안 되는 것

- **권한 필터는 검색 단계에서 적용합니다.** 2차원(등급×부서)이라 chroma `where`로
  못 내려보내, 점수 계산 후 허용 ID만 남깁니다. 권한 없는 청크는 LLM 프롬프트에 오르지 않습니다.
- **거부 1겹은 LLM 호출 전에 일어납니다.** 결정적이고 비용이 0입니다.
- **청킹은 고정 길이가 아니라 `## 제N조` 헤딩 단위입니다.** 조항 번호를 그대로 출처로 쓰기 위해서입니다.
